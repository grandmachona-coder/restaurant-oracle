System Overview

Bistro Steward is a vanilla JS PWA (~8,300 lines in index.html) backed by Firebase (Auth, Firestore, Cloud Functions) with Gemini 2.5 Flash AI for voice commands and inventory scanning. It manages the LaChona Bistro kitchen: inventory, ingredients, recipes, menus, prep status, shopping lists, and activity logging. Post-optimization: render() decoupled from persistence, O(1) Map indexes, lazy-loaded SheetJS, dead code removed, auth race condition fixed with listener fallback.

  • index.html Entire SPA: HTML + CSS + JS ~8,300 lines
  • firebase-config.js Firebase project config + Cloud Function URL 29 lines
  • firebase-adapter.js DELETED — dead code removed -477 lines
  • firebase/functions/index.js Cloud Function: CRUD, RBAC, voice, scan 784 lines
  • firebase/firestore.rules Deny-all writes, auth-read for listeners 103 lines

Section 08

Summary & Recommendations

Platform assessment with identified strengths, architectural risks, and prioritized improvement recommendations.

Strengths

  • Backend-first security model — all writes enforced through Cloud Function with 10-layer validation pipeline
  • Real-time multi-user sync via 15 Firestore listeners with conflict resolution preserving local pending changes
  • AI augmentation through Gemini 2.5 Flash — voice commands and vision-based inventory scanning
  • Comprehensive undo system covering 13 data tables with 5-state history stack
  • Differential sync — only modified records persist to cloud via debounced batching with mutex protection
  • 27 fixes applied (23 audit + 4 optimizations) — render decoupled, O(1) indexes, lazy SheetJS, dead code removed
  • Auth resilience — forced token refresh + Cloud Function fallback when Firestore listeners fail

Risks (4 of 5 Resolved)

  • Monolithic 8,300-line index.html — high cognitive load, difficult to navigate (deferred: extract ES modules incrementally)
  • O(n) array lookups — RESOLVED: IDX Map indexes provide O(1) lookups for all 11 collections, replacing 174 Array.find() calls
  • Render/persistence coupling — RESOLVED: Monkey-patch deleted. render() is pure UI; persistence via scheduleSync() in mutation functions
  • 477-line dead code — RESOLVED: firebase-adapter.js deleted from both root and deploy directories
  • SheetJS eager load (~500KB) — RESOLVED: Dynamic loadXLSX() loads library on-demand when Admin tab Excel import is used
  • Full DOM rebuild per render() — innerHTML still used, but deferred as performance is adequate at current data volumes

Key Recommendation

Platform Status: Production-Hardened

5 of 7 architectural issues have been resolved: render() decoupled from persistence, O(1) Map indexes replace 174 Array.find() calls, SheetJS lazy-loaded (~500KB saved from initial load), 477 lines of dead code deleted, and auth race condition fixed with Cloud Function fallback. The remaining investment is modularizing index.html into ES modules — this can be pursued incrementally by extracting one tab's render logic at a time. DOM patching is deferred as innerHTML performance is adequate at current data volumes (100-200 items per collection).
