💡
Core decision: Single Firebase project, multi-tenant namespacing. Do NOT create a separate Firebase project per customer — that collapses at 100 customers. Every customer gets a tenantId (UUID) in their Firebase Auth JWT custom claim. Firestore security rules enforce that they can only read their own path.

🔒 Data Isolation (Firestore Rules)

match /tenants/{tenantId}/{col}/{doc=**} {
  allow read: if
    request.auth.token.tenantId == tenantId
    && request.auth.token.approved == true;
  allow write: if false; // Cloud Function only
}

Each customer's data is physically in the same Firebase project but logically isolated. Zero cross-tenant data leakage possible with these rules.

⚡ Real-Time Sync: Already Solved

Firestore onSnapshot listeners are already the core of Bistro Steward. The web browser tab and the mobile PWA both subscribe to the same tenant namespace.

A change made on the iPad in the kitchen appears on the laptop at the bar in 100–300ms.

No additional architecture needed. This is the existing system, just namespaced per tenant.
