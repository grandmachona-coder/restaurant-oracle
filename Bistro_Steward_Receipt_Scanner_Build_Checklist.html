Receipt Scanner — Build Checklist Bistro Steward · companion to the Margin/Receipts plan · 2026-06-01 · server-spine-first (matches UPC Phase 1 order)

✅ BUILT & VERIFIED — 2026-06-02 (code-complete, not yet deployed). Stages A0–C are implemented and pass 13/13 test suites (incl. 30 new receipt tests). Capture uses native file-input + canvas compression (no Apple Vision, no getUserMedia for receipts); extraction is Gemini 2.5 Flash with a responseSchema; photos persist to Cloud Storage; the Margin ▸ Receipts dashboard does best-guess assignment + Apply (priceHistory stamped with the receipt's vendor). To go live: enable Cloud Storage, grant the functions service account the Service Account Token Creator role (for signed URLs), deploy rules→functions→hosting, then node enable-receipts-lachona.js --execute.
Locked from the plan: brand lives on the ingredient (ing.brands[]), recipes pick a brand per line (rec.ings[].brandId), one brand may be checkbox-isDefault. A receipt carries one supplier (vendorId); each line resolves to a brand. Apply writes priceHistory {date,price,vendorId,brandId}. Capture = phone; triage dashboard = web only. Two flags: receiptScanner, brandSources — both off / fail-closed, lachona first.
Two grounding facts that shape these steps (verified in code 2026-06-01):
1. Firebase Storage is not configured yet (no storage.rules, no Storage in firebase.json or app.html) — so keeping receipt photos means standing it up (step A0). The receipt image is retained in Cloud Storage; the receipt doc in Firestore holds the line items + vendor + totals + an imageRef pointer.
2. Receipt-OCR Gemini cost is already captured by the existing geminiInput/geminiOutput rollup, as long as we tag logGeminiUsage({op:'receiptScan'}). A dedicated RATE_CARD line is optional polish, not a blocker.

A4

Add op:'receiptScan' — clone of scan, receipt prompt

firebase/functions/index.js (new if (operation === 'receiptScan') block, right after the scan block ~line 1400)
  • Reuse verbatim from scan: base64 format check, imageSizeBytes cap, GEMINI_API_KEY guard, gemini-2.5-flash model, responseMimeType:'application/json', the JSON parse-with-regex-fallback, and the sanitize-then-filter pass.
  • New input: data.image, data.mimeType, data.vendorId, data.knownIngredients (D.ings names — feeds best-guess, same as scan's allIngredients).
  • New prompt = "read this restaurant supplier receipt." Output JSON: items:[{description, qty, unit, unitCost, lineTotal, barcode?, matchName, confidence}] plus optional total. Instruct it to set matchName to the closest exact name from knownIngredients.
  • Sanitize each line (clamp strings, coerce numbers) like scan does; drop empty rows.
  • Persist the image: generate a receiptId, write the decoded buffer to Cloud Storage at tenants/{tenantId}/receipts/{receiptId}.jpg via the Admin SDK (admin.storage().bucket().file(path).save(buf, {contentType})). Keep the imageRef (the gs/object path).
  • logGeminiUsage({ op:'receiptScan', ... }) and writeAuditLog(userId,userEmail,'receipt_scan', vendorName, items.length, tenantId).
  • Return { data:{ receiptId, imageRef, items, total }, error:null, _rateLimit } — the client stores these on the receipt doc.
Done when: a posted receipt returns structured line items + a stored imageRef; the JPEG is in the tenant's Storage path; usage + audit rows are written.

Stage B · Capture (phone)

Behind receiptScanner flag. Reuses the existing camera overlay + image compression. Depends on Stage A.
No Apple Vision / no native OCR. Capture is web-standard getUserMedia + a canvas grab; OCR + line-item extraction + ingredient matching all happen in the receiptScan Cloud Function via Gemini. This keeps a single cross-platform codepath (web PWA, Android, Capacitor iOS) and avoids a repeat of the UPC BarcodeDetector iOS saga (v6→v13). Apple's Vision framework is iOS-native only (no web API) and returns raw text — it wouldn't structure the receipt or match ingredients, so it'd still need an LLM pass downstream. Not used.
